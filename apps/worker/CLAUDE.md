# apps/worker

NestJS 12 application context (no HTTP server) for background work with pg-boss (ADR 0002): month-end releases, revaluation previews, held-event retries, the reconciliation check, exports and PDFs, each with its spec. Copied from Vertex Food's `apps/worker` and adapted; logging follows Vertex Hub's worker. S01 added the email outbox and the daily clean-up; S03 the daily anchor and the full export.

## Layout
- `src/main.ts`: loads the config, creates the application context, uses the pino logger, enables shutdown hooks. pg-boss's timers keep the process alive.
- `src/worker.module.ts`: `WorkerModule.forRoot(config, jobs)`: config, nestjs-pino, the app and jobs roles' databases, the files, the email transport, the queue.
- `src/core/config/`: `loadConfig(env)`: `DATABASE_QUEUE_URL` must name `mizan_queue` and `DATABASE_APP_URL` `mizan_app` (a `user` query parameter is refused), `DATABASE_JOBS_URL` `mizan_jobs` (S03), `APP_URL` (the web app's origin, the base of emailed links, as in `apps/api`), `MIZAN_FILES_DIR` (as in `apps/api`: absolute, required in production, `.data/files/` otherwise), `SMTP_URL` (`smtp://` or `smtps://`; locally compose.yaml's Mailpit), `EMAIL_FROM`, `NODE_ENV`, `LOG_LEVEL`.
- `src/core/database/`: `DatabaseModule`, one pool as `mizan_app` (`DATABASE` token), as in `apps/api`, and one as `mizan_jobs` (`JOBS_DATABASE`), which reaches across companies only through the grants and policies `packages/db`'s convention test pins (S03).
- `src/core/files/`: `FileStore` (`FilesModule`, global): the files under `MIZAN_FILES_DIR` laid out as `apps/api`'s, written from a stream through a temporary name, read whole (null when gone) and removed (no error when gone). `src/core/clock/today.ts`: `todayInDamascus()`, `dayBefore()`.
- `src/core/email/`: `EmailModule` and `EMAIL_TRANSPORT`: the server's SMTP account through nodemailer; the tests put `CapturingTransport` in its place.
- `src/core/queue/`: `QueueModule` (pg-boss as `mizan_queue` in the `pgboss` schema with `createSchema: false`; at start it installs or migrates its tables, then creates (with the job's `queueOptions`), schedules and works every job; graceful stop) and `ScheduledJob`.
- `src/jobs/<module>/<name>.job.ts`: one scheduled job per file, listed in `src/jobs/index.ts`. Pattern to copy: `src/jobs/system/heartbeat.job.ts` (`system.heartbeat`, every minute, logs `Heartbeat`). S01: `src/jobs/email/send.job.ts` (`email.send`, every minute: claims the due outbox rows with a 5-minute lease and `SKIP LOCKED`, sends them, deletes them with their token; a failure keeps its code and waits 2, 4 … 60 minutes; pg-boss keeps its runs one day) with `templates.ts` (the Arabic text from `ar.email`, times in Damascus with Latin digits), and `src/jobs/system/clean-up.job.ts` (`system.clean-up`, daily at 02:00 UTC: expired or idle sessions, expired tokens, old rate-limit rows; expired invitations marked revoked with an audit row per invitation, per company in one transaction). S03, **the pattern for a job across companies**: `src/jobs/ledger/daily-anchor.job.ts` (`ledger.daily-anchor`, 21:30 UTC, 00:30 in Damascus: as the jobs role in one transaction under an advisory lock, each company's chain head at the end of the previous day into `chain_anchors` and one `daily_anchor` email per owner listing all their companies; the email goes in through the four outbox columns the jobs role holds, as SQL, since Drizzle would name every column; `anchor(day)` for the tests), `src/jobs/company/export.job.ts` (`company.export`, every minute: the jobs role finds the queued exports; each is claimed in its own transaction, its attempt counted so one that keeps killing the worker fails at the third (`EXPORT_ATTEMPTS`), the temporary files a killed build left removed (`FileStore.removePartials`); the app role builds it in its company from a repeatable-read snapshot under a skip-locked row lock, then `ready` for 24 hours with the owner emailed, or `failed` with its code and whatever file it wrote deleted) with `archive.ts` (`writeArchive`: streamed to its file as it is built, a table at a time and each attachment opened only when the ZIP reaches it (`addReadStreamLazy`) and read as it is written and checked against the digest recorded at upload (`ATTACHMENT_CHANGED`); every company table of the registry as JSON and CSV, values as PostgreSQL prints them so amounts stay integer strings, dates whatever the DateStyle; `manifest.json` with row counts, each file's SHA-256, the ledgers' currencies, the missing attachments and the chain head; the README in Arabic and English says which currency each amount column is in and that SYP is the new pound; through yazl; `csvField` disarms formulas), and `src/jobs/company/export-expire.job.ts` (`company.export-expire`, hourly: the files past their time deleted and the rows marked `expired`).
- `test/worker.ts` (`startWorker()`, `CapturingTransport`), `test/worker.test.ts` (the boot test: the real module on a fresh database installs pg-boss as the queue role, schedules every job once however many workers boot, and works a queued job to `completed`) and `test/jobs.test.ts` (the S01 jobs, run directly), `test/trust.test.ts` (S03's jobs, run directly: anchors and emails once, the archive opened with yauzl and checked against its manifest, a failed write, the expiry). Files run one at a time (`vitest.config.ts`): the boot test's worker works the same database.

## Rules
- Queue names are `<module>.<name>` after the job's file; crons are UTC.
- Every job is idempotent: pg-boss retries, so running a job twice or concurrently leaves the same result.
- Job payloads carry ids, not records; a job loads fresh data in its own transaction.
- pg-boss runs as `mizan_queue` only, which reaches no `public` table. A job that reads company data gets the app role's database (one company, `withCompany`) or the audited `mizan_jobs` role's (cross-company, through its own policies; ADR 0003) with that job: add the module then, as Vertex Food's `jobs-database` module does. Never the owner role (ADR 0008).
- Accounting rules (releases, revaluation, settlement) are decided in `packages/ledger` and posted only through the posting function in `packages/db`; a job only triggers them.
- Explicit `@Inject(Token)` on constructor parameters, as in `apps/api`. Logs through the Nest `Logger`, never `console.log`; an error is logged through `describeForLog`, never its message.

## Tests
Run: `pnpm --filter @vertex-mizan/worker test` (needs the database URLs, `packages/db/CLAUDE.md`) · `pnpm --filter @vertex-mizan/worker typecheck`. `pnpm check:boot` starts the built API and worker together (CI).
