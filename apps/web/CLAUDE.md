# apps/web

The Vertex Mizan web app: React 19 + Vite SPA, Arabic RTL first (ADR 0009, ADR 0010), on the design system of `packages/ui`. Copied from Vertex Hub's `apps/web` and adapted. Read `brand/identity.md` and `packages/ui/CLAUDE.md` before visual work.

## Layout
- `src/main.tsx`: `DirectionProvider` (`textDirection` from `@vertex-mizan/i18n`), TanStack Query's client (a `COMPANY_NOT_SELECTED` refusal reloads the person: S01 edge case 7), TanStack Router. `index.html` gets `theme-init.js` and the font preloads from `vertexMizanWeb()` (`vite.config.ts`).
- `src/routes/`: TanStack Router file routes, kept thin (a route names its page component). `__root.tsx` holds the error and not-found pages; each page chooses its frame through a pathless layout: `_app.tsx` (the shell, and the guard `requireEnrolled`: a session with two-factor enrolled, S01 rules 1–2; its context carries `me`) or `_auth.tsx` (`AuthLayout`: sign-in, two-factor, forgot and reset password, invitation, enrolment). Pages of the active company sit under `_app/_company.tsx` (`requireCompany`: without an active company, `/companies`; S01 rule 20): its context carries `companyId` and `membership`, read with `useCompany()`; when the session's company changes (another tab, a removal) the pages load again in the new one and the old forms are dropped. A page that needs a permission declares `requirePermission` in its route (the menus only hide; the API decides). `/design-system` wraps itself in the shell, open without signing in. Pages that return somewhere take a `redirect` search parameter through `returnTo` (`lib/session.ts`). `routeTree.gen.ts` is generated by the router plugin on `dev` and `build`: never edit or read it, commit it when routes change.
- `src/components/`: app-wide pieces. `app-shell.tsx` (`AppShell`): the skip link, the Vertex Green sidebar (`md` and up) or the `Sheet` behind the menu button (phones), the top bar with the command palette (pages, theme, density) and the theme toggle. A page joins the navigation through `navItems`. `auth-layout.tsx` (`AuthLayout`, `AuthHeading`): one card under the logo. `reauth-dialog.tsx` (`useSensitiveAction`): runs a sensitive action, and on `REAUTHENTICATION_REQUIRED` asks for an authenticator code and runs it again; render its `dialog`. `form-error.tsx` (`FormError`: a refusal's Arabic text, announced, nothing for a cancelled re-authentication; `FormErrorSummary`: a form's field errors above it as `[fieldId, error]` pairs in the form's order, with `attempt` counting the refused submits). `reason-dialog.tsx` (`ReasonDialog`): an action with a written reason (`reasonSchema`), run as a sensitive action. `confirm-dialog.tsx` (`ConfirmDialog`): an action confirmed without a reason, its refusal kept in the dialog. The shell's top bar holds the company switcher; an archived company shows its banner on every page. `system-status.tsx`: `GET /api/health` through `healthQuery`.

## Rules
- UI from `@vertex-mizan/ui` only: no ad-hoc colors, fonts, spacing or hand-styled controls. A missing component goes to `packages/ui` first (ADR 0010 §7), with its place on the design-system page.
- Logical CSS only; `packages/ui/src/conventions.test.ts` checks `src/` too.
- Every text from `ar` of `@vertex-mizan/i18n` (the shell's in `ar.shell`); no literal text in components.
- Amounts only through `Amount`, `AmountInput` or a `Grid` cell; dates through `src/lib/format.ts`.
- Server state in TanStack Query; query keys start with the module name. Responses are parsed with the contract's Zod schema (`packages/contracts`).
- Every page handles loading, empty and error states.
- A form that checks its fields on submit gives each checked `Field` an `id`, counts its refused submits and renders `FormErrorSummary` above its fields (ADR 0010 §4): the summary takes focus and links to each field; the errors stay beside their fields too. In E2E, find a field's error with `fieldError(scope, text)` from `e2e/test.ts`, since the summary repeats it.

## Tests (`docs/testing.md`, "E2E")
- Playwright specs in `e2e/`, on the production build (`vite preview`). `e2e/test.ts` gives every spec its `test`: the API mocked per page (options `health`; `me`, the person `GET /api/me` answers, `signedIn` by default and `null` for no session; `api`, answers keyed by `METHOD /api/path`, a function to see the request, `refusal(status, code)` for an error; any other `/api` request fails the test), and a test fails on a page error or a Base UI console error; `GET /api/inbox/counts`, the shell's held count, answers none held unless a test's `api` says otherwise. `e2e/access-mocks.ts` and `e2e/company-mocks.ts`: S01's synthetic answers (`owner` holds every permission; `companyReads` answers every company page's reads). `e2e/chart-mocks.ts`: S02's (the service-agency chart built from `CHART_TEMPLATES`, `chartReads`), `e2e/dimension-mocks.ts` (`dimensionReads`) and `e2e/rate-mocks.ts` (`rateReads`, the tests' `today` for `page.clock`) and `e2e/entry-mocks.ts` (S03: the spec's currency purchase as entry 2026/1 and its reversal, drafts in each state, the preview, `entryReads`). `e2e/trust-mocks.ts` (S03: clean, broken and pasted integrity reports, exports in each state, `trustReads`, the `auditor`) and `e2e/trust.spec.ts` (the integrity check and the full export; one test's own answers go through `answer()`, a `page.route` before the shared mocks, never by changing the shared `api` object). `e2e/receivables-mocks.ts` (S04: the spec's M-1 shifted before the tests' today, an older M-0, a Hub item, client funds, `receivablesReads`) and `e2e/receivables.spec.ts` (the ageing, statement, item and funds pages, the palette's finders, a receipt and an invoice with items by keyboard, the preview's items, the due-date change; its `answer()` takes a query string). `e2e/inbox-mocks.ts` (S05: a posted Hub invoice and its entry 2026/21, held events of each kind the pages explain, a dismissed, a resolved and a recorded event, payloads from the contract's `eventExamplesV1`, `detailOf`, `inboxReads`) and `e2e/inbox.spec.ts` (the tabs, filters and row retry, the palette's "حدث…", each action with its request, the refusal kept in the dialog, the auditor and accountant, the Hub links on an entry and an item). `e2e/settings-mocks.ts` (S05: the service-agency mapping with `project_cost` unmapped and two events held for it, a Hub client with an active and a revoked key, `newSecret()` made at run time, `settingsReads`) and `e2e/settings.spec.ts` (the mapping and its refusal, the client's creation, rotation, revocation and edit after a fresh code, the key shown once, the auditor, the tolerance). A dialog under the re-authentication dialog is hidden from the accessibility tree while the code is asked for: wait for the action's second request before checking that it closed. `e2e/revenue-mocks.ts` (S06: the acceptance's cycle, a deposit, a released cycle, the months with a missing release and two decisions, November's preview, a late invoice held `SERVICE_PERIOD_CLOSED` and a cancelled project with their previews, a contract asset item, `revenueReads`) and `e2e/revenue.spec.ts` (the schedules, their filter and ledger switch, a schedule's page, the months and the preview, the journal opened filtered, the recognition and the split with their requests, a split outside the remainder, the auditor and the viewer). `e2e/entries.spec.ts`: the entry screen by keyboard only, `=`, lookups, the preview and its refusals, stale saves, approval, reversal, files, the journal and an account's lines. A picker's list highlights a match by hover: move the pointer away before keys. `e2e/access.spec.ts`, `e2e/company.spec.ts`, `e2e/chart.spec.ts`, `e2e/dimensions.spec.ts` and `e2e/rates.spec.ts`: the access, company, chart, dimension and rate flows. `e2e/shell.spec.ts`: the shell and the system status (database down, API unreachable); `e2e/design-system.spec.ts`: the design-system page. A `Select` opens on its chosen item, so an option above it can be out of view: pick it with the arrow keys (`choose` in `rates.spec.ts`). Import `test` and `expect` from `e2e/test.ts`, never from `@playwright/test`.
- `e2e/screens.spec.ts`: every screen in light and dark at 360, 768 and 1280 px (`widths`), with `screenshot()` attached as review evidence and no sideways page scroll (`expectNoPageOverflow`). A new screen gets its test here.
- Keys pressed right after `goto` can arrive before the page renders: wait for its heading first.
- A spec passes on the owner's machine and on CI's slower runners only when it waits for what it uses (an option rendered, a request recorded), never for a fixed time.
- Synthetic tokens, keys and secrets in mocks and tests are made at run time, never written as literals: the secret scan (`pnpm verify`, CI) refuses a literal that looks like one.

Run: `pnpm --filter @vertex-mizan/web dev` · `pnpm verify apps/web/e2e/<file>.spec.ts [--grep "<title>"]` (builds first; the whole suite runs before the PR with `pnpm verify --e2e-all`, and in CI) · `pnpm --filter @vertex-mizan/web typecheck`.
