# apps/web

The Vertex Mizan web app: React 19 + Vite SPA, Arabic RTL first (ADR 0009, ADR 0010), on the design system of `packages/ui`. Copied from Vertex Hub's `apps/web` and adapted. Read `brand/identity.md` and `packages/ui/CLAUDE.md` before visual work.

## Layout
- `src/main.tsx`: `DirectionProvider` (`textDirection` from `@vertex-mizan/i18n`), TanStack Query's client (a `COMPANY_NOT_SELECTED` refusal reloads the person: S01 edge case 7), TanStack Router. `index.html` gets `theme-init.js` and the font preloads from `vertexMizanWeb()` (`vite.config.ts`).
- `src/routes/`: TanStack Router file routes, kept thin (a route names its page component). `__root.tsx` holds the error and not-found pages; each page chooses its frame through a pathless layout: `_app.tsx` (the shell, and the guard `requireEnrolled`: a session with two-factor enrolled, S01 rules 1–2; its context carries `me`) or `_auth.tsx` (`AuthLayout`: sign-in, two-factor, forgot and reset password, invitation, enrolment). Pages of the active company sit under `_app/_company.tsx` (`requireCompany`: without an active company, `/companies`; S01 rule 20): its context carries `companyId` and `membership`, read with `useCompany()`; when the session's company changes (another tab, a removal) the pages load again in the new one and the old forms are dropped. A page that needs a permission declares `requirePermission` in its route (the menus only hide; the API decides). `/design-system` wraps itself in the shell, open without signing in. Pages that return somewhere take a `redirect` search parameter through `returnTo` (`lib/session.ts`). `routeTree.gen.ts` is generated by the router plugin on `dev` and `build`: never edit or read it, commit it when routes change.
- `src/components/`: app-wide pieces. `app-shell.tsx` (`AppShell`): the skip link, the Vertex Green sidebar (`md` and up) or the `Sheet` behind the menu button (phones), the top bar with the command palette (pages, theme, density) and the theme toggle. A page joins the navigation through `navItems`. `auth-layout.tsx` (`AuthLayout`, `AuthHeading`): one card under the logo. `reauth-dialog.tsx` (`useSensitiveAction`): runs a sensitive action, and on `REAUTHENTICATION_REQUIRED` asks for an authenticator code and runs it again; render its `dialog`. `form-error.tsx` (`FormError`: a refusal's Arabic text, announced, nothing for a cancelled re-authentication; `FormErrorSummary`: a form's field errors above it as `[fieldId, error]` pairs in the form's order, with `attempt` counting the refused submits). `reason-dialog.tsx` (`ReasonDialog`): an action with a written reason (`reasonSchema`), run as a sensitive action. `confirm-dialog.tsx` (`ConfirmDialog`): an action confirmed without a reason, its refusal kept in the dialog. The shell's top bar holds the company switcher; an archived company shows its banner on every page. `system-status.tsx`: `GET /api/health` through `healthQuery`.
- `src/features/<module>/`: one folder per domain with its pages. `auth/` (S01): the sign-in, two-factor, forgot and reset password, invitation, enrolment and account security pages, `validation.ts` (the contract's schemas, Arabic messages). `design-system/design-system-page.tsx` (`/design-system`): every component of `packages/ui` with synthetic data; listed in the navigation in development only, reachable always (the screenshot tests use it). `company/` (S01): the companies list, a new company, the company settings, `ledger-fields.tsx` (the ledgers form, Vertex Media's shape, `ledgersOf`), `company-queries.ts` (`companyQuery`, `useSwitchCompany`: drops every company query, then opens `/`). `members/`: members and invitations (`members-queries.ts`). `audit/`: the audit log, filters and an entry's changes (`audit-values.tsx`: each recorded value as the app shows it). `chart/` (S02): `/chart` (`chart-page.tsx`: the tree with filters, row actions, the templates of an empty chart, the Excel export; `?new=true`, from the palette, opens a new account), `account-sheet.tsx` (`AccountSheet`: a new or existing account in a side sheet, only the changed fields sent, locked fields disabled after first use; `nextChildCode`), `/chart/roles` (`account-roles-page.tsx`), `chart-queries.ts` (accounts, templates, roles). `dimensions/` (S02): `/dimensions` (`dimensions-page.tsx`: a tab per type, its values with search and paging, value and type dialogs, the Hub link, archive and restore; a contract's client through `DimensionPicker`), `dimension-queries.ts` (types, value pages). `rates/` (S02): `/rates` (`rates-page.tsx`: a pair's rows per type, `bulletinDays` for the status of the last 30 days, the rate in force, the record dialog that turns `RATE_REASON_REQUIRED` into a correction with a reason, pairs; `?record=bulletin`, from the palette, opens the record dialog), `/rates/calendar` (`rate-calendar-page.tsx`), `rate-queries.ts`; a rate row's "entries that used it" sheet (S03). `entries/` (S03): `/entries` (`journal-page.tsx`: filters, the ledger switch; `?find=number`, from the palette, focuses the number filter), `/entries/:id` (`entry-page.tsx`: both ledgers, conversions, files, the chain; reverse and copy), `/entries/new` and `/drafts/:id` (`entry-editor-page.tsx` loads, `entry-editor.tsx` is the keyboard entry screen: a `Grid` with `enterMoves="next"` from tablet width, `LineCards` on a phone, the entry keys of `keymap` on its root, Alt+↓ pickers that give the focus back through the grid's `handle`, `=` through `balancingAmount()`, save then post or submit by the approval switch, `DRAFT_CHANGED` with a reload that starts the screen over; `?open=preview` previews a draft its first save created), `draft-lines.ts` (the working copy of a draft: lines with stable keys, `draftInputOf`, `dealtRatePairs`, `dimensionColumns`), `preview-panel.tsx` (`PreviewPanel`, `Refusals`, `refusalText`), `/drafts` (`drafts-page.tsx`: the tabs, `?view=awaiting` from the palette), `/accounts/:id/lines` (`account-lines-page.tsx`), `entry-parts.tsx` (`EntryNumberText`, `EntryLinesTable`, `AttachmentsCard`, the pickers' options and labels), `entry-queries.ts` (with `useDimensionCatalog`: every value of every type, since lines name values by id). `home/`: the first page.
- `src/lib/`: `api.ts` (`api`: `/api` calls with the session cookie, the answer parsed with the contract's schema, a refusal thrown as `ApiError` with its code and `details` (the publication day of `RATE_MISSING`); `company` sends `X-Mizan-Company` on a company write, S01 rule 22; `listOf` parses a list; `errorText`, `hasCode`; `download` saves a file answer, an export or an attachment, with the company header; `upload` sends one file as multipart), `session.ts` (`meQuery`: `GET /api/me`, `null` without a session; the guards `requireSession` and `requireEnrolled`; `safeRedirect` keeps return addresses inside the app; `activeMembership`, `can`, `requireCompany`, `requirePermission`, `useCompany`), `fragment-token.ts` (`useFragmentToken`: an emailed link's `#token=`, read once and removed from the address bar), `format.ts` (dates and counts: `formatLocale`, Damascus time, month names, `damascusDayBounds` for date filters, calendar days with `formatDay`, `formatShortDay`, `damascusToday`, `addDays`, `isoWeekday`; entry numbers with `formatEntryNumber` (`2026/12`, or `2026-27/12` in a fiscal year spanning two calendar years) and `parseEntryNumber`; `formatKilobytes`; never amounts), `health.ts`.
- `vite.config.ts`: dev server `127.0.0.1:5173` proxying `/api` to the API (`API_HOST`/`API_PORT` from the root `.env`, default `127.0.0.1:3300`); `vite preview` on `127.0.0.1:4173`.

## Rules
- UI from `@vertex-mizan/ui` only: no ad-hoc colors, fonts, spacing or hand-styled controls. A missing component goes to `packages/ui` first (ADR 0010 §7), with its place on the design-system page.
- Logical CSS only; `packages/ui/src/conventions.test.ts` checks `src/` too.
- Every text from `ar` of `@vertex-mizan/i18n` (the shell's in `ar.shell`); no literal text in components.
- Amounts only through `Amount`, `AmountInput` or a `Grid` cell; dates through `src/lib/format.ts`.
- Server state in TanStack Query; query keys start with the module name. Responses are parsed with the contract's Zod schema (`packages/contracts`).
- Every page handles loading, empty and error states.
- A form that checks its fields on submit gives each checked `Field` an `id`, counts its refused submits and renders `FormErrorSummary` above its fields (ADR 0010 §4): the summary takes focus and links to each field; the errors stay beside their fields too. In E2E, find a field's error with `fieldError(scope, text)` from `e2e/test.ts`, since the summary repeats it.

## Tests (`docs/testing.md`, "E2E")
- Playwright specs in `e2e/`, on the production build (`vite preview`). `e2e/test.ts` gives every spec its `test`: the API mocked per page (options `health`; `me`, the person `GET /api/me` answers, `signedIn` by default and `null` for no session; `api`, answers keyed by `METHOD /api/path`, a function to see the request, `refusal(status, code)` for an error; any other `/api` request fails the test), and a test fails on a page error or a Base UI console error. `e2e/access-mocks.ts` and `e2e/company-mocks.ts`: S01's synthetic answers (`owner` holds every permission; `companyReads` answers every company page's reads). `e2e/chart-mocks.ts`: S02's (the service-agency chart built from `CHART_TEMPLATES`, `chartReads`), `e2e/dimension-mocks.ts` (`dimensionReads`) and `e2e/rate-mocks.ts` (`rateReads`, the tests' `today` for `page.clock`) and `e2e/entry-mocks.ts` (S03: the spec's currency purchase as entry 2026/1 and its reversal, drafts in each state, the preview, `entryReads`). `e2e/entries.spec.ts`: the entry screen by keyboard only, `=`, lookups, the preview and its refusals, stale saves, approval, reversal, files, the journal and an account's lines. A picker's list highlights a match by hover: move the pointer away before keys. `e2e/access.spec.ts`, `e2e/company.spec.ts`, `e2e/chart.spec.ts`, `e2e/dimensions.spec.ts` and `e2e/rates.spec.ts`: the access, company, chart, dimension and rate flows. `e2e/shell.spec.ts`: the shell and the system status (database down, API unreachable); `e2e/design-system.spec.ts`: the design-system page. A `Select` opens on its chosen item, so an option above it can be out of view: pick it with the arrow keys (`choose` in `rates.spec.ts`). Import `test` and `expect` from `e2e/test.ts`, never from `@playwright/test`.
- `e2e/screens.spec.ts`: every screen in light and dark at 360, 768 and 1280 px (`widths`), with `screenshot()` attached as review evidence and no sideways page scroll (`expectNoPageOverflow`). A new screen gets its test here.
- Keys pressed right after `goto` can arrive before the page renders: wait for its heading first.
- A spec passes on the owner's machine and on CI's slower runners only when it waits for what it uses (an option rendered, a request recorded), never for a fixed time.
- Synthetic tokens, keys and secrets in mocks and tests are made at run time, never written as literals: the secret scan (`pnpm verify`, CI) refuses a literal that looks like one.

Run: `pnpm --filter @vertex-mizan/web dev` · `pnpm verify apps/web/e2e/<file>.spec.ts [--grep "<title>"]` (builds first; the whole suite runs before the PR with `pnpm verify --e2e-all`, and in CI) · `pnpm --filter @vertex-mizan/web typecheck`.
