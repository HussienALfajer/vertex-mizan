# apps/web

The Vertex Mizan web app: React 19 + Vite SPA, Arabic RTL first (ADR 0009, ADR 0010), on the design system of `packages/ui`. Copied from Vertex Hub's `apps/web` and adapted. Read `brand/identity.md` and `packages/ui/CLAUDE.md` before visual work.

## Layout
- `src/main.tsx`: `DirectionProvider` (`textDirection` from `@vertex-mizan/i18n`), TanStack Query's client (a `COMPANY_NOT_SELECTED` refusal reloads the person: S01 edge case 7), TanStack Router. `index.html` gets `theme-init.js` and the font preloads from `vertexMizanWeb()` (`vite.config.ts`).
- `src/routes/`: TanStack Router file routes, kept thin (a route names its page component). `__root.tsx` holds the error and not-found pages; each page chooses its frame through a pathless layout: `_app.tsx` (the shell, and the guard `requireEnrolled`: a session with two-factor enrolled, S01 rules 1–2; its context carries `me`) or `_auth.tsx` (`AuthLayout`: sign-in, two-factor, forgot and reset password, invitation, enrolment). Pages of the active company sit under `_app/_company.tsx` (`requireCompany`: without an active company, `/companies`; S01 rule 20): its context carries `companyId` and `membership`, read with `useCompany()`; when the session's company changes (another tab, a removal) the pages load again in the new one and the old forms are dropped. A page that needs a permission declares `requirePermission` in its route (the menus only hide; the API decides). `/design-system` wraps itself in the shell, open without signing in. Pages that return somewhere take a `redirect` search parameter through `returnTo` (`lib/session.ts`). `routeTree.gen.ts` is generated by the router plugin on `dev` and `build`: never edit or read it, commit it when routes change.
- `src/components/`: app-wide pieces. `app-shell.tsx` (`AppShell`): the skip link, the Vertex Green sidebar (`md` and up) or the `Sheet` behind the menu button (phones), the top bar with the command palette (pages, theme, density) and the theme toggle. A page joins the navigation through `navItems`. `auth-layout.tsx` (`AuthLayout`, `AuthHeading`): one card under the logo. `reauth-dialog.tsx` (`useSensitiveAction`): runs a sensitive action, and on `REAUTHENTICATION_REQUIRED` asks for an authenticator code and runs it again; render its `dialog`. `form-error.tsx` (`FormError`): a refusal's Arabic text, announced (nothing for a cancelled re-authentication). `reason-dialog.tsx` (`ReasonDialog`): an action with a written reason (`reasonSchema`), run as a sensitive action. The shell's top bar holds the company switcher; an archived company shows its banner on every page. `system-status.tsx`: `GET /api/health` through `healthQuery`.
- `src/features/<module>/`: one folder per domain with its pages. `auth/` (S01): the sign-in, two-factor, forgot and reset password, invitation, enrolment and account security pages, `validation.ts` (the contract's schemas, Arabic messages). `design-system/design-system-page.tsx` (`/design-system`): every component of `packages/ui` with synthetic data; listed in the navigation in development only, reachable always (the screenshot tests use it). `company/` (S01): the companies list, a new company, the company settings, `ledger-fields.tsx` (the ledgers form, Vertex Media's shape, `ledgersOf`), `company-queries.ts` (`companyQuery`, `useSwitchCompany`: drops every company query, then opens `/`). `members/`: members and invitations (`members-queries.ts`). `audit/`: the audit log, filters and an entry's changes (`audit-values.tsx`: each recorded value as the app shows it). `chart/` (S02): `/chart` (`chart-page.tsx`: the tree with filters, row actions, the templates of an empty chart, the Excel export; `?new=true`, from the palette, opens a new account), `account-sheet.tsx` (`AccountSheet`: a new or existing account in a side sheet, only the changed fields sent, locked fields disabled after first use; `nextChildCode`), `/chart/roles` (`account-roles-page.tsx`), `chart-queries.ts` (accounts, templates, roles, dimension types). `home/`: the first page.
- `src/lib/`: `api.ts` (`api`: `/api` calls with the session cookie, the answer parsed with the contract's schema, a refusal thrown as `ApiError` with its code; `company` sends `X-Mizan-Company` on a company write, S01 rule 22; `listOf` parses a list; `errorText`, `hasCode`; `download` saves a file answer, an export, with the company header), `session.ts` (`meQuery`: `GET /api/me`, `null` without a session; the guards `requireSession` and `requireEnrolled`; `safeRedirect` keeps return addresses inside the app; `activeMembership`, `can`, `requireCompany`, `requirePermission`, `useCompany`), `fragment-token.ts` (`useFragmentToken`: an emailed link's `#token=`, read once and removed from the address bar), `format.ts` (dates and counts: `formatLocale`, Damascus time, month names, `damascusDayBounds` for date filters; never amounts), `health.ts`.
- `vite.config.ts`: dev server `127.0.0.1:5173` proxying `/api` to the API (`API_HOST`/`API_PORT` from the root `.env`, default `127.0.0.1:3300`); `vite preview` on `127.0.0.1:4173`.

## Rules
- UI from `@vertex-mizan/ui` only: no ad-hoc colors, fonts, spacing or hand-styled controls. A missing component goes to `packages/ui` first (ADR 0010 §7), with its place on the design-system page.
- Logical CSS only; `packages/ui/src/conventions.test.ts` checks `src/` too.
- Every text from `ar` of `@vertex-mizan/i18n` (the shell's in `ar.shell`); no literal text in components.
- Amounts only through `Amount`, `AmountInput` or a `Grid` cell; dates through `src/lib/format.ts`.
- Server state in TanStack Query; query keys start with the module name. Responses are parsed with the contract's Zod schema (`packages/contracts`).
- Every page handles loading, empty and error states.

## Tests (`docs/testing.md`, "E2E")
- Playwright specs in `e2e/`, on the production build (`vite preview`). `e2e/test.ts` gives every spec its `test`: the API mocked per page (options `health`; `me`, the person `GET /api/me` answers, `signedIn` by default and `null` for no session; `api`, answers keyed by `METHOD /api/path`, a function to see the request, `refusal(status, code)` for an error; any other `/api` request fails the test), and a test fails on a page error or a Base UI console error. `e2e/access-mocks.ts` and `e2e/company-mocks.ts`: S01's synthetic answers (`owner` holds every permission; `companyReads` answers every company page's reads). `e2e/chart-mocks.ts`: S02's (the service-agency chart built from `CHART_TEMPLATES`, `chartReads`). `e2e/access.spec.ts`, `e2e/company.spec.ts` and `e2e/chart.spec.ts`: the access, company and chart flows. Import `test` and `expect` from `e2e/test.ts`, never from `@playwright/test`.
- `e2e/screens.spec.ts`: every screen in light and dark at 360, 768 and 1280 px (`widths`), with `screenshot()` attached as review evidence and no sideways page scroll (`expectNoPageOverflow`). A new screen gets its test here.
- Keys pressed right after `goto` can arrive before the page renders: wait for its heading first.

Run: `pnpm --filter @vertex-mizan/web dev` · `pnpm verify apps/web/e2e/<file>.spec.ts [--grep "<title>"]` (builds first; the whole suite runs in CI) · `pnpm --filter @vertex-mizan/web typecheck`.
