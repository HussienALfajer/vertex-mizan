# apps/web

The Vertex Mizan web app: React 19 + Vite SPA, Arabic RTL first (ADR 0009, ADR 0010), on the design system of `packages/ui`. Copied from Vertex Hub's `apps/web` and adapted. Read `brand/identity.md` and `packages/ui/CLAUDE.md` before visual work.

## Layout
- `src/main.tsx`: `DirectionProvider` (`textDirection` from `@vertex-mizan/i18n`), TanStack Query's client (a `COMPANY_NOT_SELECTED` refusal reloads the person: S01 edge case 7), TanStack Router. `index.html` gets `theme-init.js` and the font preloads from `vertexMizanWeb()` (`vite.config.ts`).
- `src/routes/`: TanStack Router file routes, kept thin (a route names its page component). `__root.tsx` holds the error and not-found pages; `index.tsx` (`/`, the home page) and `design-system.tsx` (`/design-system`, open without signing in) wrap themselves in `AppShell`. The screens were removed on 2026-11-19 to be rebuilt; a new screen adds its route here. The guards stay in `lib/session.ts` for the new screens (`requireSession`, `requireEnrolled`, `requireCompany`, `requirePermission`), naming the sign-in, enrolment and companies addresses as plain `href`s until those pages exist again. Pages that return somewhere take a `redirect` search parameter through `returnTo` (`lib/session.ts`). `routeTree.gen.ts` is generated by the router plugin on `dev` and `build`: never edit or read it, commit it when routes change.
- `src/components/`: app-wide pieces. `app-shell.tsx` (`AppShell`): the skip link, the Vertex Green sidebar (`md` and up) or the `Sheet` behind the menu button (phones), the top bar with the command palette (pages, theme, density) and the theme toggle. A page joins the navigation through `navItems` (now the home page and, in development, the design-system page); the palette lists those pages, the theme and the density. `auth-layout.tsx` (`AuthLayout`, `AuthHeading`): one card under the logo. `reauth-dialog.tsx` (`useSensitiveAction`): runs a sensitive action, and on `REAUTHENTICATION_REQUIRED` asks for an authenticator code and runs it again; render its `dialog`. `form-error.tsx` (`FormError`: a refusal's Arabic text, announced, nothing for a cancelled re-authentication; `FormErrorSummary`: a form's field errors above it as `[fieldId, error]` pairs in the form's order, with `attempt` counting the refused submits). `reason-dialog.tsx` (`ReasonDialog`): an action with a written reason (`reasonSchema`), run as a sensitive action; `errorDetail` shows what a refusal names under its text. `confirm-dialog.tsx` (`ConfirmDialog`): an action confirmed without a reason, its refusal kept in the dialog. The shell's top bar holds the company switcher; an archived company shows its banner on every page. `system-status.tsx`: `GET /api/health` through `healthQuery`.
- `src/features/<module>/`: one folder per domain with its pages. `home/` (`/`: the product and the system's health). `design-system/design-system-page.tsx` (`/design-system`): every component of `packages/ui` with synthetic data; listed in the navigation in development only, reachable always (the screenshot tests use it). Every other screen (S01–S12: sign-in, companies, members, audit, chart, dimensions, rates, entries, integrity, exports, receivables, periods, reports, opening, cash, projects) was removed on 2026-11-19 so new screens can be built on the same API, components and design system; git history keeps them.
- `src/lib/`: `api.ts` (`api`: `/api` calls with the session cookie, the answer parsed with the contract's schema, a refusal thrown as `ApiError` with its code and `details` (the publication day of `RATE_MISSING`); `company` sends `X-Mizan-Company` on a company write, S01 rule 22; `listOf` parses a list; `errorText`, `hasCode`; `download` saves a file answer, an export or an attachment, with the company header; `upload` sends one file as multipart), `company.ts` (`companyQuery`, `useSwitchCompany`: drops every company query, then opens `/`), `session.ts` (`meQuery`: `GET /api/me`, `null` without a session; the guards `requireSession` and `requireEnrolled` (enrolled, or exempt: S01 rule 2, owner 2026-11-16; an exempt person's sign-in goes straight back, `reauth-dialog.tsx` asks them for the password and the security page offers enrolment); `safeRedirect` keeps return addresses inside the app; `activeMembership`, `can`, `requireCompany`, `requirePermission`), `fragment-token.ts` (`useFragmentToken`: an emailed link's `#token=`, read once and removed from the address bar), `format.ts` (dates and counts: `formatLocale`, Damascus time, month names, `damascusDayBounds` for date filters, calendar days with `formatDay`, `formatShortDay`, `damascusToday`, `addDays`, `isoWeekday`; entry numbers with `formatEntryNumber` (`2026/12`, or `2026-27/12` in a fiscal year spanning two calendar years) and `parseEntryNumber`; `formatKilobytes`; never amounts), `health.ts`.
- `pwa.ts` (`vertexMizanPwa()`, build only): the installable app. `manifest.json` (name, `rtl`, standalone, Vertex Green, the brand's 192, 512 and maskable icons emitted as hashed assets), `offline.html` (self-contained, text from `ar.common.app`) and `sw.js`, registered by `src/main.tsx` in production: it never answers `/api` or caches company data, and only replaces a failed page load with the offline page; its cache name changes with that page. nginx serves all three under `location /` with `no-cache`. `e2e/pwa.spec.ts` checks them; every other spec runs with service workers blocked (`playwright.config.ts`).
- `vite.config.ts`: dev server `127.0.0.1:5173` proxying `/api` to the API (`API_HOST`/`API_PORT` from the root `.env`, default `127.0.0.1:3300`); `vite preview` on `127.0.0.1:4173`.

## Rules
- UI from `@vertex-mizan/ui` only: no ad-hoc colors, fonts, spacing or hand-styled controls. A missing component goes to `packages/ui` first (ADR 0010 §7), with its place on the design-system page.
- Logical CSS only; `packages/ui/src/conventions.test.ts` checks `src/` too.
- Every text from `ar` of `@vertex-mizan/i18n` (the shell's in `ar.shell`); no literal text in components.
- Amounts only through `Amount`, `AmountInput` or a `Grid` cell; dates through `src/lib/format.ts`.
- Server state in TanStack Query; query keys start with the module name. Responses are parsed with the contract's Zod schema (`packages/contracts`).
- Every page handles loading, empty and error states.
- A form that checks its fields on submit gives each checked `Field` an `id`, counts its refused submits and renders `FormErrorSummary` above its fields (ADR 0010 §4): the summary takes focus and links to each field; the errors stay beside their fields too. In E2E, find a field's error with `fieldError(scope, text)` from `e2e/test.ts`, since the summary repeats it.

## Tests (`docs/testing.md`, "E2E")
- Playwright specs in `e2e/`, on the production build (`vite preview`). `e2e/test.ts` gives every spec its `test`: the API mocked per page (options `health`; `me`, the person `GET /api/me` answers, `signedIn` by default and `null` for no session; `api`, answers keyed by `METHOD /api/path`, a function to see the request, `refusal(status, code)` for an error; any other `/api` request fails the test), and a test fails on a page error or a Base UI console error. `e2e/shell.spec.ts`: the shell and the system status (database down, API unreachable); `e2e/design-system.spec.ts`: the design-system page; `e2e/pwa.spec.ts`: the installable app. The screens' specs and their mocks left with the screens (2026-11-19); a new screen brings its own. A `Select` opens on its chosen item, so an option above it can be out of view: pick it with the arrow keys. A picker's list highlights a match by hover: move the pointer away before keys. Import `test` and `expect` from `e2e/test.ts`, never from `@playwright/test`.
- `e2e/screens.spec.ts`: every screen in light and dark at 360, 768 and 1280 px (`widths`), with `screenshot()` attached as review evidence and no sideways page scroll (`expectNoPageOverflow`). A new screen gets its test here.
- Keys pressed right after `goto` can arrive before the page renders: wait for its heading first.
- A spec passes on the owner's machine and on CI's slower runners only when it waits for what it uses (an option rendered, a request recorded), never for a fixed time.
- Synthetic tokens, keys and secrets in mocks and tests are made at run time, never written as literals: the secret scan (`pnpm verify`, CI) refuses a literal that looks like one.

Run: `pnpm --filter @vertex-mizan/web dev` · `pnpm verify apps/web/e2e/<file>.spec.ts [--grep "<title>"]` (builds first; the whole suite runs before the PR with `pnpm verify --e2e-all`, and in CI) · `pnpm --filter @vertex-mizan/web typecheck`.
